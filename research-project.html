Research and engineering account

The project record follows the investigation from its research question and historical context through implementation, evaluation and interpretation. It provides a place to document decisions, discoveries, unsuccessful approaches and supporting evidence as the work develops.

Terminology notes record the definitions and amendments relevant to the investigation. Infrastructure as Code (IaC), cloud deployment and communications integrations are considered where they affect the system under study.

    Browser demonstration editor

    The editor supports small HTML, CSS and JavaScript demonstrations. The initial example displays the project’s planned fictional test case; it illustrates the interface rather than demonstrating a completed AI implementation or research finding.

    No model is running. Model APIs are not connected; the preview policy restricts API and resource requests.

    The preview is intended for trusted experimental code. The frame restricts API/resource requests, forms and parent-page access; it is not a hardened untrusted-code service, and resource-heavy scripts can affect browser performance. It cannot run the Python starters or hosted models. Exported HTML retains the same content restrictions.

    Where the work actually runs

    Current: browser

    The editor, local draft storage and HTML/CSS/JavaScript preview run on the visitor’s device. The website supplies static files; exported files remain separate from the published record.

    Current: GitHub workspace

    The linked folder holds source references, a research dossier, roadmap, evidence register and Python starter. GitHub stores the files; the Python starter requires execution in a suitable Python environment.

    Future: deliberate integration

    Local models, Python services, cloud GPUs and commercial APIs need a selected runtime, dependencies, authentication and cost controls. No backend or installed-app integration is connected here.

    What a research release contains

    A release fixes a reviewable version of the work: report, permitted code/data, figures, run instructions, evidence records, attribution, limitations and change notes. The public case study explains it; a commit/tag or archival record identifies the exact artefacts. Publication, independent review and scientific validation are separate statuses.

    • Claims supported by the available evidence, including failures and contrary results.
    • Version, environment, licence, contribution record and reproducibility/accessibility limits.
    • Citation information and a version-specific identifier where an archival deposit exists.
    • Separate records for originator correspondence, submissions, responses and any established collaboration.
