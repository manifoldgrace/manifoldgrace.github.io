01 · THE CONNECTION

Where the internet comes from

The global internet is a network of independently operated networks exchanging traffic. A household normally receives internet access through an internet service provider (ISP). Fibre, cable, DSL, cellular and satellite are different access paths. A router creates a local network; running one does not create an independent internet uplink.

ISP / upstream connection→ONT, modem or cellular gateway→Router + firewall→Wi-Fi / switch→Devices & services

Internet access

ISP service, permitted mobile tethering or other contracted uplinks. Alternative routes differ in coverage, speed, latency and total cost.

Local-only network

Devices can share data, printers and local services through a router or switch without an external internet connection. Useful for isolated experiments.

Hosting and publishing

A locally hosted service still needs suitable connectivity, DNS, secure external access and service maintenance. A static website can instead be hosted on GitHub Pages.

A server rack is an enclosure, not a prerequisite for networking or AI. Rack illustrations are useful for identifying components, but do not imply that every home requires a rack, high-voltage equipment or complex cabling.

03 · VIRTUAL BEFORE PURCHASING

Free and lower-cost ways to model the system

Three types of substitute must be distinguished: a simulator represents network behaviour; a virtual machine runs operating-system software on existing hardware; and a hosted service supplies remote compute or storage. None automatically replaces a household's physical ISP connection.

Network simulator

Cisco Packet Tracer

Network topology and configuration practice. Education tool, free with eligible registration; not a substitute for a real ISP or production firewall.

Network emulation

GNS3

Free/open-source network modelling with virtual devices. Some vendor images are separately licensed. Hardware resources determine scale.

Virtual router/firewall

OPNsense

Runs as a virtual firewall on supported hypervisors. Best introduced within an isolated lab before considering any change to a functioning household router.

Virtual computers

VirtualBox

Virtual machines for isolated operating-system and software experiments. Depends on the host's CPU, RAM and storage.

Hosted AI practice

Google Colab

Notebook-based experiments with variable free resources and restrictions. Accelerator access is not guaranteed.

Local inference

Ollama

A local model runner for supported machines. Model suitability depends on memory, model format, context and system workload.

Suggested virtual-first concept sequence

First draw the topology and check the devices you already own. Next model routing and segmentation in a simulator. Then examine a virtual firewall in an isolated VM. Finally compare local versus hosted AI compute. These are staged learning objectives, not instructions to alter an existing household network.

04 · CYBERSECURITY

Security controls in the right places

Internet boundary and ISP router→Traffic policy and segmentation→Protected devices and accounts→Logs, monitoring and recovery

Firewalls

Network controls may operate at packet, connection and application levels. A web application firewall protects HTTP-oriented applications; it does not replace endpoint protection.

Endpoint security

Keep operating systems and applications updated; use device encryption, appropriate anti-malware protection and supported security tools. EDR provides additional monitoring where justified.

Identity

Unique credentials, a password manager, multi-factor authentication and carefully scoped administrative permissions protect accounts and services.

Segmentation

Keep guest or smart-home devices separate from sensitive research devices where supported by the router. Network separation must be verified, not inferred from a label.

Backups

Use independent, versioned, protected copies and periodically verify restoration. Backup and system availability are different requirements.

Monitoring

Maintain relevant security logs, alerts and response responsibilities. AI-assisted classification can help prioritise review but is not a guarantee of detection.

How the security diagrams should be interpreted

The OSI-layer diagrams are educational approximations, not an exhaustive classification of products; protective functions overlap layers. DDoS, DNS spoofing, person-in-the-middle activity, botnets and malware illustrate distinct risks. One supplied graphic labels an ARP-related example as IP spoofing; those concepts should not be treated as interchangeable. The home firewall rules image is a schematic example, not a universal configuration to copy.

05 · COMPUTE / ACCELERATION

When CPUs, GPUs and remote accelerators matter

OptionSuitable forLimitation
Existing CPU / integrated GPUNetwork labs, coding, admin, lightweight inferenceSlower for some large parallel workloads
Local discrete GPUGraphics, supported AI inference and training experimentsVRAM, heat, electricity and cost constraints
Cloud GPU / notebookOccasional acceleration without owning a powerful cardTime limits, quotas, network reliance, data handling and fees
Multi-GPU / interconnectSpecialised large-model workloadsComplexity, compatibility, hardware cost and communication overhead
Hosted AI APIAI features without managing model-serving hardwareProvider terms, ongoing cost, privacy and model availability

The uploaded VRAM/model matrices and NVLink numbers are useful comparison prompts, not verified compatibility guarantees. Model size, quantisation, context length, KV cache, software compatibility and available system memory all affect practical performance.

07 · ALTERNATIVE COMBINATIONS

Setups compared by purpose, not expense

Existing equipment

ISP router + current laptop or mobile device + appropriately secured backups and supported cloud services.

Virtual learning lab

Existing computer + network simulator + isolated virtual machines; no rack or GPU purchase required.

Research and automation

Source registry + protected data storage + notebooks or hosted APIs + reviewed outputs + evidence log.

Local AI experimentation

Device with suitable memory + local model runtime + benchmark and safety controls, with hosted acceleration only where needed.

Extended home infrastructure

Switches, APs, storage and power protection added only to satisfy evidenced reliability, capacity or recovery requirements.
