# Publication Archive Generator — reusable educational implementation

**Initiated:** 13 November 2026. **Status:** original reference implementation committed; successful automated generation and deployment must be verified separately.

## Aim
Demonstrate lawful, source-linked, compact public archiving with daily, weekly, monthly, annual and all-record PDF indexes plus CSV, JSON and searchable HTML. This prototype indexes only Manifold Grace's own dated public productivity-log entries.

## Why this approach?
PDF is for convenient reading, printing and offline reference. CSV/JSON make verifiable indexing, comparison and machine-assisted analysis possible. HTML improves navigability and screen-reader compatibility. PDF/UA conformance is **not** claimed; a formal accessibility audit is required.

## Source-to-output design
1. Input: productivity-log.html with dated log blocks and table.progression-table.
2. Parser: scripts/build_publication_archive.py extracts visible titles and links, retains the block's public log date, and deduplicates records.
3. Provenance: keep the source entry anchor and first evidence URL, while declaring that the dates are **log dates**, not original publication dates of externally cited articles.
4. Publisher files: archive/metadata/publication-records.json, .csv and periods.json.
5. PDF bundles: archive/downloads/daily/YYYY-MM-DD.pdf, weekly/YYYY-MM-DD.pdf (Monday-start), monthly/YYYY-MM.pdf, yearly/YYYY.pdf, all-records.pdf.
6. Browser: publication-evidence-archive.html reads the manifests and builds collapsible download groups and a searchable record list.
7. CI: .github/workflows/publication-archive-pdfs.yml runs on relevant pushes, every day, or by manual dispatch. It generates, validates PDF signatures and commits output changes.

## Local instructions
Requires Python 3.12+, Beautiful Soup 4.12.3 and ReportLab 4.2.5 (the versions pinned in CI).

    python -m pip install beautifulsoup4==4.12.3 reportlab==4.2.5
    python scripts/build_publication_archive.py

The command writes generated bundles into archive/. It does not read or copy remote third-party article bodies.

## Adaptation for another publisher
Replace extract_records with a parser for **your own published catalogue or sources you are authorised to use**. Preserve canonical URL, a stable source ID, original publication date, revisions, correction status and licence per record. Record the difference between source publication, a later update, and the date of archive capture. Do not call the collection complete without independent coverage evaluation. Consider feeds, a permitted public API, JATS/XML metadata, CMS exports, or an existing publications database.

## Transparency and limitations
- No bypass of paywalls, security controls or access restrictions.
- No licensed publisher text reproduced in PDFs.
- Citation of external sources does not establish that their claims are verified.
- PDFs generated by ReportLab are **not** certified as tagged or PDF/UA compliant; accessible HTML and machine data are provided.
- Existing pages are public and may themselves contain dated material; sensitive material must be removed at source before archiving.
- A scheduled workflow is not evidence that a job executed or deployment completed. Inspect the workflow logs and generated manifests.
- GitHub Actions' repository write permission is required to commit outputs.
- GitHub Pages source settings must publish the relevant branch/directory, or a dedicated Pages workflow must deploy the archive.
