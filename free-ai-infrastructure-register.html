Free & Low-Cost AI Infrastructure Register

Developed as a cost-first reference for people building their own AI systems. The register distinguishes truly local software, limited free cloud access, commercially hosted services and existing Manifold Grace infrastructure. It supports the AI Public Adviser and the wider AI systems roadmap.

Audit status: 10 November 2026. 63 tool entries are documented; these are candidates, not installed products. No new accounts, API keys, deployments or external provider integrations have been created by this register. Free-tier usage limits and licences can change. Not all free software performs like paid frontier services, and computer hardware still costs money.

Three ways to begin

Entirely local

Ollama or llama.cpp + Open WebUI + SQLite + locally stored documents.

No model API subscription; requires a capable computer and locally licensed model.

Cloud free allocation

Gemini or GroqCloud + Cloudflare Workers AI + Supabase, subject to current quotas.

Useful when local hardware is insufficient; credentials and privacy conditions require attention.

Research-first hybrid

Existing GitHub Pages and GitHub Actions + permitted feeds + source verification + SQLite/Qdrant + model fallback.

Preserves a free public information layer and avoids premature dependency on one provider.

Security and trust must be assessed before integration

Every technology is listed with foreseeable technical and information-handling risks. This does not imply that a named provider or its staff have acted improperly. Nationality, employee background or geography alone does not establish intent; assess published data-handling policies, jurisdiction, access controls, incident response, audits and verifiable contractual terms. Open-source software may reduce dependence on a service provider but does not eliminate malicious packages, inaccurate models or local security problems.

Data handling default: keep sensitive or unpublished information local where feasible, restrict tokens to the minimum permissions, avoid embedding credentials in publicly deployed pages, document third-party processing and test a supplier's revocation and deletion process. Never send personal case files or confidential research to a free model API solely because it is free.

Review 20 documented cases of software compromise, data exposure, third-party risk and governance failure.

Risk review questions and evidence requirements
  • Who processes, stores, trains on, reviews, logs and deletes prompts, attachments, model outputs and metadata?
  • What contractual protections, permitted subprocessors, processing locations and lawful disclosure requirements apply?
  • Can access to accounts, API tokens, support functions and agent tools be independently controlled, logged and revoked?
  • Are the developer, model weights, software dependencies and update processes auditable?
  • Can the project be exported or moved if a company changes ownership, licensing or access?
  • What happens after an incident: notifications, corrections, backups, independent investigations and proven recovery?

Registration and integration sequence

Stage 0 — No new accounts needed

Retain existing GitHub infrastructure; audit current pages and existing Graphify CI; prepare source schemas, synthetic evaluation cases and a consent-based test dataset. Experiment with open-source local tools on suitable hardware before creating subscriptions.

Stage 1 — Optional account-based trials

Evaluate one free model API, one extraction provider only if needed, and one cloud storage/search service only if the existing environment is insufficient. Each connection must have documented purpose, allowed data, quota, provider terms, key custody and a revocation procedure. Do not publish API keys on GitHub Pages.

Stage 2 — Integration pilot

Implement a server-side model gateway, local source cache, explicit citation record, independent-source deduplication, request budget caps, failure fallback, data retention limits and human review for any consequential action. Compare providers using identical prompts and datasets.

Stage 3 — Public demonstration

Deploy only once evidence coverage, cost per request, latency, factual accuracy, uncertainty calibration, accessibility and responsible-use controls have been measured. Public-safety information remains accessible independent of commercial subscriptions.

How to determine whether a free tool is nearly as capable

A free alternative can only be described as comparable after task-specific evaluation. For the AI Public Adviser, measure source coverage, claim attribution accuracy, factual error rate, contradiction detection, refusal to guess when evidence is inadequate, response latency, privacy safeguards and total monthly operating cost.

Recommended comparison: local model vs free hosted model vs a stronger benchmark model, using the same set of public questions, evidence passages and blinded scoring. Publish individual failure cases and date all results.
